用户选择动作副作用
allow_once本次放行不记忆

durable 事实块挂在 CompactController 上，每轮重组 system prompt 时注入 —— 被摘要冲掉的历史靠它兜底。 外置化旁路：工具输出 > 50 KiB 落盘留指针 + 2 KiB 预览；bash 输出 > 20 000 字符做 head 14k + tail 5k 裁剪； 配额超限按 LRU 驱逐，重放时对失效指针标注 status="missing"。

10. 事件字典：19 种事件与落盘/回放语义

事件落 transcript映射回 LLM messages触发时机
message是是（user / assistant 文本）用户输入、助手回复、终止提示
function_call是是（assistant tool_calls）模型产出每个工具调用
function_call_result是是（tool_result / role=tool）每个工具返回（含拒绝文案）
reasoning是否模型返回 reasoning_content
file-history-snapshot是否写工具前后各一条
permission_request / resolved / expired是否ASK 生命周期
turn_budget_warning是否第 32 轮
skill_loaded是否自动匹配加载或 use_skill
run_started / run_finished / run_aborted是否run 边界
artifact_presented是否present_files 成功且有卡片
context_usage是否每轮估算 + 官方用量校准各一次
context_limit_exceeded是否出口②
final_prompt是否每轮 sanitize 后的真实请求快照
error是否预留错误通道
assistant_delta / reasoning_delta否（sequence=0）否流式 chunk，仅 SSE
回放链路：bootstrap_messages() 只认 message / function_call / function_call_result 三类， 按「assistant 挂起 → 遇到结果即 flush」重建成对结构；重放时外置指针会被核验，失效的标注 missing。

一句话总结：循环的每一处失败都被设计成「降级继续」而不是「崩溃终止」—— 工具异常变结果文本、压缩失败变原样、摘要失败变剪枝、权限超时变拒绝、子代理异常变错误摘要。 真正会让 run 停下来的只有五件事：模型说完了、上下文彻底超窗、40 轮用尽、用户 abort、provider 抛错。
